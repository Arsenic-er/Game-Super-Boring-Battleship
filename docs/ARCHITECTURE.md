# 技术架构

## 核心原则

战斗模拟不依赖 3D 引擎。渲染、玩家输入、规则 AI 和未来强化学习策略都通过明确接口读取或控制模拟状态。

```text
玩家输入 ─┐
          ├─ Controller → 确定性战斗模拟 → 状态快照 → Babylon.js 渲染
规则 AI ──┤
强化学习 ─┘
```

## 分层

- `src/sim`：固定时间步、航行、弹道、碰撞、分区伤害与维修。
- `src/controllers`：玩家和 AI 将观察转换为标准控制命令。
- `src/render`：把模拟状态显示为低负载 3D 场景。
- `src/ui`：HUD、提示、画质与对局状态。

## 强化学习接口

AI 控制器只接收观察并输出动作，不直接修改游戏对象：

```text
Observation: 自舰状态、敌舰相对方位/距离、模块状态、装填状态
Action:      车钟、舵角、瞄准点、是否开火
Reward:      命中、造成伤害、存活、胜负、无效射击惩罚
```

规则 AI 与强化学习策略可互换。后续无渲染运行多个模拟实例，训练过程无需创建海面、摄像机或粒子效果。

## 联机演进

v0.1 的模拟先在浏览器运行。局域网阶段把相同模拟移动到权威服务器：

- 客户端只提交操作。
- 服务器计算移动、炮弹、命中和伤害。
- 客户端接收状态快照并插值显示。
- Windows 主机启动本地服务器，其他玩家通过局域网地址加入。

## 初始性能预算

- 默认 1280×720，目标 30 FPS。
- 无实时阴影、屏幕空间反射和体积效果。
- 单方向光加环境光。
- 程序化低面数舰船；纹理需求极少。
- 粒子、水柱和弹道标记有严格数量上限。
- 海面为单网格和廉价材质。
- 逻辑采用固定 60 Hz；渲染可独立降至 30 FPS。

## 可复现性

模拟使用固定时间步和项目内伪随机数生成器。相同初始种子与动作序列应产生相同结果，便于测试、回放、联机同步及强化学习评估。
