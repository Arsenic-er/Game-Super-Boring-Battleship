# 0.7.4 — Official Babylon water acceptance

## Scope

The user selected Babylon's official WaterMaterial. Production changes are based
on `79d9bab` in the canonical server worktree on `codex/v072-historical-models`.
The rendering package is pinned to 9.16.1, matching the existing engine.

- Replaced the scrolling RGB ocean and thin box waves with world-space normal
  layers, animated geometry, reflection and refraction.
- Low quality uses a 256-pixel reflection/refraction pair and a three-frame
  refresh interval; medium uses 512 pixels. Nearby ship lists are bounded.
- Clear, scattered, overcast, rain-squall and sea-fog have bounded wave presets.
- A submerged seabed replaces the fake shallow-water surface overlay. Approved
  underwater targets can appear through refraction. Both normal layers keep
  their position when the camera-centred mesh moves.
- Ship/torpedo wakes and underwater camera transitions sample the same surface
  equation as the official vertex shader. Animation follows simulation time,
  including fixed-step updates and pause.
- All water normal pixels are generated by original project code. No external
  textures, paid assets or game meshes were imported. Apache-2.0 notices updated.
- No balance, save format, LAN protocol or control binding changed.

## Input issue found during release testing

The existing global button hover/active transform overrode the capture-recovery
button's `translateX(-50%)`. Its hit area moved between press and release, so a
trusted click landed on the background ancestor instead of the button. Explicit
hover/focus/active transforms now preserve its centred position. The pointer-lock
controller itself was not changed. Early failed QA runs were not counted as passes.

## Limits

This is the selected lightweight official water foundation, not an FFT ocean,
breaking-wave foam simulation, volumetric depth absorption or finished submarine
renderer. Full-resolution reflection of every distant ship is intentionally not
enabled. No multi-client LAN test was repeated for this render-only update.
Existing dependency-audit findings were not auto-fixed by unrelated upgrades.
